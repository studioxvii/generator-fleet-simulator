Read this page top to bottom for the quickest path through individual control, grouped operations, timed scenarios, background refresh behavior, and Modbus integration.

1. Work The Fleet Status Tab

  1. Filter or search for the units you want to inspect.
  2. Select rows to prepare bulk commands or sub-fleet assignment.
  3. Click any row to keep one generator live in the detail panel.
  4. Use the page controls when operating large simulated fleets.

2. Use The Selected Unit Panel

The right-hand detail panel mirrors the reference repo’s grouped control model. Engine actions, breaker operations, automation, and fault injection stay separated so demos are easier to follow.

3. Organize Sub-Fleets

Create named sub-fleets from the selected generators, then issue coordinated start, stop, utility fail, or restore commands to that group. This is the fastest way to stage transfer scenarios without touching the full fleet.

4. Run Scenario Timelines

Scenario Timelines are executable runbooks. Select a preset, review its timed steps, click Apply Runbook, and watch the monitor report elapsed time, completed steps, and assertion results. Use Load Into Editor or Clone when you need to modify a preset before saving a new timeline.

5. Understand Refresh Behavior

The selected generator detail stays live over Socket.IO, while the fleet table refreshes on demand and on a slower cadence. That keeps large fleets responsive without losing current detail on the unit you are focused on.

6. Read The Modbus Tab

Select a unit to inspect the live register map with raw values, scaling, engineering values, binary alarm words, and decoded active bits. This matches the reference repo’s protocol-oriented presentation rather than a plain register dump.

7. Send Commands Through Modbus

Write a command value to register 20 on the target unit ID. The simulator applies the command and clears the register back to zero after reading it.

1 = Start 2 = Stop 3 = Close Gen Breaker 12 = Parallel Mode 13 = Island Mode 14 = Transfer Mode 8 = Reset Alarms 10 = Utility Fail 11 = Restore Utility 20-27 = Core faults 28-39 = Extended faults Reg 16 = Parallel setpoint (kW x10) Reg 17 = Alarm Word 3

Button Color Rules

Button colors are semantic, not decorative. The same meaning is used throughout the app.

GreenStart, restore, reset, and recovery actions.
GrayNavigation, mode changes, and non-destructive setup actions.
BlueApply, save, and focused confirmation actions.
OrangeCaution paths such as utility failure drills.
RedE-Stop, delete, remove, and injected fault actions.

Common Demo Flow

  1. Select a unit, confirm it is in auto mode, and trigger utility fail.
  2. Watch the state move through CRANKING to RUNNING and pick up load.
  3. Open the Modbus tab for that same unit and verify register changes.
  4. Create a sub-fleet, assign several units, and repeat the scenario at group scale.
  5. Inject a fault, verify the alarm words, then reset and restore utility.
